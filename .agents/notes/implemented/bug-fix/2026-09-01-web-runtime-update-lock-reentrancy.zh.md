# Agent Note: Web 运行时更新器复用生命周期锁进行重启

Status: implemented

[English](2026-09-01-web-runtime-update-lock-reentrancy.md) | 中文

## Problem

受管 Web 更新器在切换运行时版本并重启后台服务期间持有生命周期锁。如果在这个临界区调用公开的 `start.mjs` 入口，子进程管理器会再次尝试获取同一把锁，因此确认更新后虽然可以成功下载并暂存新版本，却会在重启阶段失败并回滚。

## Decision

管理器为已经持有生命周期锁的调用方提供不再加锁的启动和停止操作。更新器直接导入启动操作，在激活和回滚期间等待它完成。公开的 `start.mjs` 和 `stop.mjs` 仍然会先获取锁，再调用这些操作，因此并发的用户生命周期命令仍保持串行。

## Alternatives considered

**在重启前释放锁。** 这样会允许另一个生命周期命令在写入 `current.json` 和确认启动成功之间观察或改变未完成的切换状态。

**让更新器在独立进程中调用公开入口。** 独立进程无法安全地重新进入这把锁，还会增加一个故障点，却没有带来更好的隔离，因为更新器已经控制同一个运行时根目录。

**移除生命周期锁。** 没有这把锁时，并发更新、启动和停止可能在另一个操作使用活动版本或 PID 文件时替换它们。

## Consequences

确认后的更新可以在整个切换过程中保持一个锁持有者并重启受管服务。不加锁操作只是内部协调入口，不会通过浏览器 RPC 暴露。

## Testing

更新器单元测试和语法检查均通过。打包的 `rc.13` 实例成功检查 GitHub Release 并暂存 `rc.14`；第一次真实激活暴露了这次锁重入缺陷，随后测试实例已回滚到 `rc.13` 并成功重启。后续发布会使用修正后的激活路径进行端到端验证。
