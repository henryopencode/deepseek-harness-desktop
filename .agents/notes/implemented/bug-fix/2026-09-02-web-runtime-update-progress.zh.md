# Agent Note: Web 运行时更新进度

Status: implemented

[English](2026-09-02-web-runtime-update-progress.md) | 中文

## Problem

浏览器确认更新后，受管更新器还可能下载归档、安装依赖、编译本地 Whisper 并重启服务，因此页面会长时间保持忙碌。版本轮询只能识别完成，无法说明操作正在推进还是已经卡住。

## Decision

受管更新器会在 `.dsh-runtime` 下原子写入 `update-progress.json`，记录阶段、百分比、版本、可选字节数、安装步骤、步骤开始时间和失败诊断。它会先获取生命周期锁，再写入检查更新阶段；竞争更新会直接退出，不改写正在进行的进度记录。Host 通过只读的 `host.updateStatus` RPC 暴露这个文件，并在返回前校验阶段和数值字段。安装期间浏览器轮询该 RPC，页面重新加载后会恢复正在进行的更新而不会再次启动更新器，并且只显示或按已确认发布版本对应的目标版本处理失败；有界的版本轮询仍然负责确认服务重启完成。当前页面可安装的本地或已授权远程更新会保持不可关闭的提示；读取到与目标版本匹配的 `completed` 记录后，页面只提供重新加载页面的操作，浏览器自身的刷新命令也等效。当前页面不能安装更新时保持静默，除非观察到已有正在进行或已完成的受管更新。归档和校验文件优先通过 GitHub Assets API 下载，该接口会直接重定向到资产主机；API 下载失败时回退到 Release 的浏览器下载地址。激活版本时会把当前生命周期脚本同步到运行时根目录，使成功更新同时安装后续请求使用的、支持状态查询的更新器。

## Verification

浏览器和 Host API 测试覆盖状态轮询、目标版本过滤、进度显示、失败报告、安装期间真实卸载并重新挂载页面，以及新增 RPC 约定。更新器测试覆盖按字节报告进度、GitHub Assets API 优先与回退、持久化阶段、完成状态以及锁竞争时保留正在进行的安装记录。打包的 Web 运行包通过真实发布源升级，并检查活动版本、HTTP 就绪状态和可见进度状态。

## Alternatives considered

**只显示静态的忙碌提示。** 长时间的首次更新无法与卡住的进程区分，用户也没有可用诊断。

**直接从 detached 更新器串流进度。** 浏览器或服务重连时会丢失串流；原子状态文件保留最新事实，并通过拥有更新生命周期的同一个 Host 提供读取。

**让浏览器解析更新器日志。** 日志文本是容易变化的展示通道，无法提供有类型的阶段、百分比或经过校验的失败字段。

## Consequences

运行时保留一个临时进度文件；更新进行时可以安全读取其中最新的有效记录。服务器提供长度时下载进度按字节计算；依赖安装会报告 JavaScript 依赖、Whisper 配置、Whisper 编译和运行时校验，并显示当前步骤的已用时。没有状态更新器的旧归档仍通过版本轮询完成，新激活的归档则提供详细进度。
