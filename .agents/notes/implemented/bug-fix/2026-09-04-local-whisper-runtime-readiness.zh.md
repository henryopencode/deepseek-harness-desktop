# Agent Note: 本地 Whisper 运行时就绪检查

Status: implemented

[English](2026-09-04-local-whisper-runtime-readiness.md) | 中文

## Problem

本地语音 provider 把可执行文件发现交给 `nodejs-whisper`。缺少随附的 `whisper-cli` 时，该依赖会在第一次录音请求中启动 CMake 配置和 C++ 编译。构建失败会与模型或网络失败折叠成同一条消息，并且并发录音可能在模型准备阶段发生竞争。

## Decision

provider 会在调用依赖前检查已安装的 `nodejs-whisper` 包中是否存在可用的 `whisper-cli`；如果运行时安装尚未准备它，则立即失败。原生编译仍由 Web 运行时安装器负责，安装器已有对应的安装阶段进度。模型准备按路径使用 Promise 锁，下载到唯一临时文件，校验 GGML 头，仅在文件有效时原子重命名到模型目录。`describe()` 只有在所选模型和可执行文件都可用时才报告就绪。Host 日志保留底层诊断，浏览器收到稳定的“运行时未准备好”提示。

## Alternatives considered

**保留 `nodejs-whisper` 在录音请求中的隐式构建。** 不采用，因为麦克风操作可能意外耗费数分钟编译原生代码，且失败无法与下载失败区分。

**在每个 provider 实例中构建可执行文件。** 不采用，因为多个服务可能竞争修改已安装的依赖，而运行时安装已经拥有依赖和原生准备的职责。

**接受任意非空的下载模型文件。** 不采用，因为中断下载或 HTML 错误响应可能非空但无法被 whisper.cpp 读取；GGML 头是激活前成本很低的格式检查。

## Consequences

第一次录音不再启动无界的原生编译。运行时不完整时会给出可执行的重新安装提示，有效模型不会被部分下载覆盖。多个请求共享模型准备流程，转写本身仍由已有的 busy 守卫串行执行。源码部署必须先使用带 CMake 和本机工具链的运行时安装器，才能使用本地语音。

## Verification

provider 测试使用带有效 GGML 头的夹具，覆盖异常模型下载、禁用自动下载、缺少可执行文件时拒绝，以及现有转写行为。运行时包使用仓库提供的 Node 22 运行时完成类型检查，并运行定向本地语音 provider 测试。
